### 1.5 Remove Hardcoded Translation Fallbacks

**Problem:** Everywhere I wrote `t['admin.name'] ?? 'Name'` — the `?? 'Name'` is a hardcoded English fallback that defeats the purpose of i18n.

**Why it's wrong:** If `t['admin.name']` is missing, it means the translation wasn't loaded, not that it should fallback to English hardcoded text. The fix is to ensure translations ARE loaded, not to provide a hardcoded fallback.

**Action:**
1. Find all `?? 'Fallback'` patterns in admin pages:
   - `t['admin.name'] ?? 'Name'`
   - `t['admin.slug'] ?? 'Slug'`
   - `t['admin.status'] ?? 'Status'`
   - `t['admin.actions'] ?? 'Actions'`
   - `t['admin.portfolioType'] ?? 'Type'`
   - `t['admin.published'] ?? 'Published'`
   - `t['admin.draft'] ?? 'Draft'`
   - `t['admin.confirmDelete'] ?? 'Confirm'`
   - etc.
2. Replace with unconditional: `t['admin.name']`
3. If a key is truly missing from the DB, add the translation entry to the DB
4. Never use `??` as a fallback for translations. Zero exceptions.
