## Summary
fix: Prune old Docker images on server after deploy to prevent disk full

## Problem
Each deploy creates a new Docker image on the VPS, but the Ansible deploy playbook never cleans up old images. Over multiple deploys, 12+ old images (349MB each) accumulated, consuming critical disk space on the 14GB root partition and causing the VPS to run out of space.

## Solution
Added post-deploy tasks to the Ansible deploy.yml playbook that: 1) Derive the image repository name from app_image_ref, 2) Remove all images for that repository except the latest 2 (current + previous for rollback), 3) Prune dangling images to clean up orphaned layers.

   post_tasks:

+    # Each deploy creates a new image tag. Old images pile up on the
+    # small 14GB VPS root partition unless cleaned. Keep the current and
+    # previous (for rollback), remove the rest.
+
+    - name: Compute image repository from app_image_ref
+      set_fact:
+        app_image_repo: "{{ app_image_ref | regex_replace(':[^:]+$', '') }}"
+
+    - name: Prune old app images (keep latest 2)
+      shell: |
+        set -e
+        images=$(docker images "{{ app_image_repo }}" -q 2>/dev/null | tail -n +3)
+        if [ -n "$images" ]; then
+          echo "$images" | xargs -r docker rmi -f
+          echo "PRUNED"
+        fi
+      register: deploy_prune_result
+      changed_when: "'PRUNED' in deploy_prune_result.stdout"
+
+    - name: Prune dangling images
+      community.docker.docker_prune:
+        images: true
+        images_filters:
