# PM3 Shop — вынесено за пределы первой версии (v1)

**Date:** 2026-09-03
**Return:** планирование shop-модуля приостановлено — вернуться к этому файлу после завершения текущего сайта (this site).
**Status:** Fixed (решения сессии планирования)

Этот файл фиксирует **всё, что сознательно вынесено из v1** shop-модуля PM3:
причину и триггер возврата. Основной план: `docs/plans/shop-framework-enhancement.md`
(журнал решений D1–D15, L1–L5, C1–C4; юридический пакет — §9; консоль PM — §10;
этапы — §11).

Правило: пункт возвращается в объём, когда появляется **конкретный клиент/запрос**
или меняется гипотеза — а не «на всякий случай».

## Вынесено из v1

| # | Область | Что это | Почему вне v1 | Когда возвращать |
|---|---|---|---|---|
| 1 | **Личный кабинет покупателя** | `FEATURES.buyerAccounts` (заказы, повторный заказ, возвраты онлайн) | Гостевой checkout + отслеживание `/order/[number]` по номеру+телефону закрывают базовую потребность без отдельной поверхности и auth (D8) | Первый клиент / падение конверсии |
| 2 | **SMS-уведомления** | Статусы заказа по SMS | Email + Telegram покрывают v1; SMS = платный адаптер (D12) | Клиент, у которого «email не читают» |
| 3 | **Несколько сотрудников магазина с правами** | Менеджер (заказы), кладовщик (остатки) и т.п. | v1 = один аккаунт владельца (D12); ролевая сетка внутри Shop не нужна одному человеку | Рост команды клиента |
| 4 | **Полноценные отчёты/аналитика** | Продажи по периодам/товарам, аналитика | v1: дашборд KPI + выгрузка заказов CSV (D14) | Первый клиент / тариф |
| 5 | **Конкретные платёжные адаптеры** | ЮKassa, Т-Банк, Сбер, СБП | Провайдер не выбран; ядро даёт интерфейс + sandbox (D3, §8). Подключение мерчанта — задача под клиента | Первый клиент (у него договор эквайринга) |
| 6 | **Конкретные адаптеры доставки** | СДЭК, Почта России, Boxberry/5Post | То же: интерфейс в ядре, v1 = ручные методы + самовывоз | Первый клиент (его договор с перевозчиком) |
| 7 | **Маркетплейсы и YML-фиды** | Синхронизация Ozon/WB/Яндекс Маркет; выгрузка YML | Гипотеза каналов продаж не подтверждена; это отдельные адаптеры (`CatalogImportSource`) | Запрос клиента. YML — дёшево, кандидат сразу после v1 |
| 8 | **Отзывы, избранное, промо-движок** | Промокоды/правила скидок, рейтинги, wishlist | v1: только скидка конфигом (compare-at + «от N ₽»); доверие на старте даёт качество | Клиент / конкуренция в нише |
| 9 | **Наложенный платёж и собственная ККТ продавца** | 54-ФЗ чек при наложенном, интеграция с кассой мерчанта | v1: чеки через платёжного провайдера. Наложенный требует ККТ и договора мерчанта | Вертикаль с наложенным платежом |
| 10 | **Честный знак, ЕГАИС, ограниченные категории** | Маркировка одежды/обуви, алкоголь и т.п. | Вертикально-специфично (ГИС МТ, документооборот); ядро нейтрально (D1) | Конкретная вертикаль |
| 11 | **Полноценный EAV / движки наборов атрибутов по категориям** | Runtime-атрибуты с формами и фильтрами по категориям | Ядро даёт «шов»: типизированные значения + декларативные определения (принцип 2, D6) | Клиент с экзотической структурой каталога |
| 12 | **Мультивалютность / мультиязычные магазины / переводы значений модификаторов** | RUB + RU single-locale в v1 | Все заказы на рынке стартуют RU/RUB (D5) | Клиент-экспортёр |
| 13 | **B2B** | Счета, оплата по счёту, юрлица | v1 = B2C (D2) | Клиент с оптовым каналом |
| 14 | **Консоль PM (fleet-обслуживание)** | Ops-страницы в магазине, бэкапы, алерты, версии/откат | Нет реальных деплоев — инструмент не на чем применять; границы ролей (shopkeeper/PM) уже заложены в v1. **Спецификация зафиксирована**: решения C1–C4, §10 плана | Первый реальный деплой (M6) |
| 15 | **Runtime-редактирование определений атрибутов владельцем** | Владелец добавляет «схему» через админку | Определения = код project-слоя (граница builder/owner; принцип 4) | Постоянно не планируется — только через PM |

## Сознательно отклонено (в v2 без пересмотра не возвращается)

| Что | Почему отклонено |
|---|---|
| Гибридная модель цены «база + варианты, продаётся и то и то» | Двух источников истины по цене нет ни на одной платформе; всегда продаётся вариант (D7). Наследование цены (`??`) покрывает кейс «цена одна» |
| Runtime EAV как ядро v1 | Монолит вместо шва; каждый клиент платит сложность (принцип 2) |
| Обязательная регистрация покупателя перед покупкой | RU-покупатель уходит; гостевой checkout первичен (D8) |
| Интеграции с Meta (Facebook/Instagram) | Запрещены в РФ; соцсети = VK/Telegram |
